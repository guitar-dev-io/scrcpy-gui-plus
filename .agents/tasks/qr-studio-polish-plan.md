## Decisions

1. Nav cards replace the pill tablist in the same component (`QrStudioHeader.tsx`, split out `QrNavCards.tsx` to keep files < 250 lines). Same `role="tablist"`/`tab`, `aria-selected`, roving tabindex, arrow/Home/End handling (move the existing handler). Subtitles/numbers live in `destinations.ts` (`subtitle` field). Compact mode (< 1280 container) keeps number badge + icon + title and hides the subtitle (title stays as visible text, no horizontal scroll); icon-only fallback is dropped (cards use `grid grid-cols-5 gap-2` with `min-w-0`, `truncate`). Rationale: roles/keyboard are already correct; only the visuals change.
2. Coral comes from new CSS custom properties defined once in `src/index.css` under `.qr-studio-root` (`--qr-coral: #ff4f57`, `--qr-coral-strong: #f53f4c`, `--qr-text: #f5f7fa`, `--qr-text-muted: #cbd5e1`, `--qr-text-subtle: #94a3b8`, `--qr-panel`, `--qr-border`). There is no existing coral token in `index.css` (only `--status-danger: #ff5c72`, `--primary` violet), so "existing token" is satisfied by consolidating the `#ff4f57` literals already used across qr-studio into one token rather than adding a theme-wide change. Do not change `--primary`.
3. F1 fix at the root: keep QR panels deliberately dark in every theme (they are hard-coded navy; making them theme-aware is a far larger redesign). Add `className="qr-studio-root"` to the page root and replace `text-white`/`hover:text-white` in `src/components/qr-studio/*.tsx` (non-test) with `text-[color:var(--qr-text)]` / `hover:text-[color:var(--qr-text)]` utility classes that the light-mode remap does not touch. Add a belt-and-braces rule `[data-mode='light'] .qr-studio-root .text-white { color: var(--qr-text) }` (and for `.text-zinc-*`) for any stragglers/shared children. Overlays: if runtime check shows portaled content wrong in light mode, give `overlayHost` content the same token scope (class on the host/portal root) rather than touching other modules.
4. F2: add `src/services/tauriRuntime.ts` exporting `DESKTOP_ONLY_MESSAGE = 'Requires the desktop app'`, `class DesktopRequiredError extends Error`, and `friendlyError(reason)` that maps any `TypeError` whose message contains `invoke`/`__TAURI` (or non-Tauri env) to `DesktopRequiredError`. Guard with `isTauri()` in `generateQrSvg`, `launchDeepLink`, and every function in `qrDeviceService.ts` (throw `DesktopRequiredError` before calling `invoke`). UI shows `error.message` only when it is a `DesktopRequiredError` or other non-raw text; `LivePreview` renders "Requires the desktop app" (no "Preview failed:" prefix) for it. Do not touch other services outside QR Studio.
5. Library pagination: the brief requires page numbers and a "12 per page" select. Add real pagination in `LibraryPanel.tsx`: `pageSize` state (options 12, 24, 48, 96; default 12), `page` state reset on filter/search/view change and clamped to range; the visible slice is `filtered.slice((page-1)*pageSize, page*pageSize)`; footer reads `Showing a-b of N items`, numbered page buttons (with ellipsis for > 7 pages, `aria-current="page"`, prev/next), and the `Select` (`aria-label="Items per page"`). Keep `useWindowedList` for the list view (rows) so large pages stay cheap; grid view renders the page slice directly. This replaces the old "windowed first/last index" wording for the status line. Record the deviation from design 5.5 in the final report.
6. Details panel tabs: `QrDetails.tsx` gets a `role="tablist"` with Details (name, type, content, folder, tags, notes, dates), Design (style swatches, size, EC, preview), Actions (download, copy, edit, duplicate, send to device, launch, trash) using the same arrow-key tab pattern as the nav (extract a tiny `useRovingTabs` helper only if reused by both; otherwise duplicate minimally).
7. Verification scripts and seed helpers live in `/tmp` only (never `src/`). Seeding is done through the browser tool by writing `localStorage['scrcpy-gui-plus:qr-studio:v2']` (key from `qrStudioService.ts` `QR_STUDIO_V2_STORAGE_KEY`; copy the exact record shape from `src/types/qrStudio.ts` and `qrStudioStore.ts` fixtures in `useQrStore.test.tsx`) via `evaluate_script`, not via app code.
