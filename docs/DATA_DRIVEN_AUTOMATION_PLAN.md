# Data-driven Automation Plan

อัปเดตล่าสุด: 26 สิงหาคม 2569  
สถานะเอกสาร: กำลังพัฒนา  
ขอบเขต: Script Manager / Maestro Builder

## เป้าหมาย

ทำให้ผู้ใช้เลือกไฟล์ข้อมูลทั่วไป แล้วนำแต่ละรายการไปทำงานกับ Maestro YAML ได้โดยไม่ผูกกับชื่อไฟล์ ชื่อชีต หรือรูปแบบธุรกิจใดธุรกิจหนึ่ง พร้อมตรวจสอบผลและทำงานต่อจากจุดที่หยุดได้

รูปแบบข้อมูลเป้าหมาย:

- Excel `.xlsx`
- CSV `.csv`
- TSV `.tsv`
- JSON `.json`

ตัวอย่างการใช้งานที่ต้องรองรับ:

- ถ้ายังไม่มีรายการใน UI ให้สร้างใหม่
- ถ้ามีรายการแล้ว ให้เลือกและไปเมนูถัดไป
- เลื่อนหารายการเมื่อยังไม่ปรากฏบนหน้าจอ
- ทำหนึ่งรายการหรือหลายรายการตามข้อมูลในไฟล์
- นำรายการหลักมาทำงานร่วมกับรายการย่อย เช่น `สาขา × บัญชี Audit`
- บันทึกผลสำเร็จ/ล้มเหลวและกลับมาทำต่อได้

## งานที่กำลังทำ

### ระยะที่ 1 — ความปลอดภัยและตรวจสอบก่อนรัน

- [x] ใส่ค่าของแต่ละรายการผ่านส่วน `env:` ของ Maestro YAML อย่างปลอดภัย
- [x] ป้องกันค่าที่มีอักขระพิเศษ บรรทัดใหม่ `:`, `#`, เครื่องหมายคำพูด และ `${...}` ทำให้ YAML เสีย
- [x] คงตัวแปร runtime ของ Maestro ที่ไม่ได้มาจากไฟล์ข้อมูลไว้ตามเดิม
- [x] แสดง Resolved YAML ของรายการตัวอย่างก่อนกด Run
- [x] เพิ่มชุดทดสอบค่าข้อมูลพิเศษและ YAML ที่มี `env:` เดิม

### ระยะที่ 2 — หลาย Dataset

- [x] โหมด Single Dataset
- [x] โหมด Cross Join เช่น `615 สาขา × 2 บัญชี = 1,230 งาน`
- [x] เลือกและจับคู่ตัวแปรแยกแต่ละ Dataset
- [x] ตรวจชื่อ Variable ซ้ำระหว่าง Dataset
- [x] แสดงจำนวนงานทั้งหมดก่อนรันและจำกัดไว้ที่ 10,000 งานต่อ Batch
- [ ] เพิ่มโหมด Lookup/Join ด้วยคีย์สำหรับไฟล์ที่มีความสัมพันธ์กัน

### ระยะที่ 3 — ควบคุม Batch และทำต่อ

- [ ] เลือกพฤติกรรมเมื่อพบข้อผิดพลาด: หยุด / ทำต่อ / Retry
- [ ] ตั้งจำนวน Retry และเวลารอก่อนลองใหม่
- [ ] แสดง Current/Total, รายการปัจจุบัน และเวลาที่ใช้
- [ ] Pause, Resume และ Stop อย่างปลอดภัย
- [ ] บันทึก Checkpoint เพื่อปิดโปรแกรมแล้วกลับมาทำต่อได้
- [ ] เลือกเริ่มใหม่เฉพาะรายการ Failed หรือ Not Run

### ระยะที่ 4 — ผลลัพธ์และการเขียนกลับ

- [ ] บันทึก Row ID, สถานะ, Error, เวลาเริ่ม และเวลาจบ
- [ ] สร้างไฟล์ผลลัพธ์ข้างไฟล์ต้นทางเป็นค่าเริ่มต้น เพื่อไม่แก้ข้อมูลเดิมโดยไม่ตั้งใจ
- [ ] รองรับการเขียนผลกลับ CSV/TSV/JSON โดยสร้าง Backup ก่อน
- [ ] รองรับการเขียนผลกลับ XLSX โดยรักษาชีต สูตร และรูปแบบเดิม
- [ ] ให้ผู้ใช้เลือก `สร้างไฟล์ผลลัพธ์ใหม่` หรือ `อัปเดตไฟล์ต้นทาง`
- [ ] Export รายงาน Batch เป็น JSON/CSV

### ระยะที่ 5 — การแปลงข้อมูล

- [ ] เพิ่ม Derived Variable จากหลายคอลัมน์
- [ ] รองรับ Trim, Prefix/Suffix, Replace, Regex และ Default value
- [ ] รองรับหลาย Filter แบบ AND/OR
- [ ] Preset การจับคู่คอลัมน์ต่อ Flow
- [ ] ตรวจชนิดข้อมูล วันที่ และเลขที่มีศูนย์นำหน้า
- [ ] รองรับ CSV encoding/delimiter ที่หลากหลาย
- [ ] พิจารณารองรับ `.xls` หลังรูปแบบหลักเสถียร

## หลักการด้านความปลอดภัย

- ไม่แก้ไฟล์ข้อมูลต้นทางโดยอัตโนมัติ
- ก่อนเขียนทับต้องสร้าง Backup และให้ผู้ใช้เลือกอย่างชัดเจน
- จำกัดขนาดไฟล์ จำนวนแถว และจำนวนงาน Cross Join
- ห้ามค่าจากไฟล์เปลี่ยนโครงสร้าง YAML หรือแทรกคำสั่งใหม่
- เก็บข้อมูลสำคัญใน Log เท่าที่จำเป็น และควรซ่อนค่าที่ผู้ใช้กำหนดว่าเป็นข้อมูลลับ
- Stop ต้องหยุดหลังคำสั่งปัจจุบันจบ ไม่ทิ้งไฟล์ผลลัพธ์ในสภาพเสียหาย

## เกณฑ์พร้อมใช้งาน

- อ่านไฟล์ทั้ง 4 รูปแบบด้วยโครงสร้างคอลัมน์ทั่วไปได้
- รัน Single Dataset และ Cross Join ได้โดยผลลัพธ์ตรงกับจำนวนที่ Preview
- ค่าพิเศษไม่ทำให้ YAML เสียและไม่สามารถแทรกคำสั่ง Maestro ได้
- เมื่อโปรแกรมหยุดกลางทาง สามารถ Resume โดยไม่รันรายการที่สำเร็จซ้ำ
- ทุกงานมีสถานะและข้อความผิดพลาดที่ย้อนตรวจสอบได้
- การเขียนผลกลับต้องมี Backup และผ่านการทดสอบว่าไม่ทำลายชีต/ข้อมูลเดิม
- Frontend tests, TypeScript check, production build และ Rust tests ผ่านทั้งหมด

## ลำดับดำเนินงานที่แนะนำ

1. Safe env injection + Resolved YAML Preview
2. Cross Join หลาย Dataset
3. Retry / Continue / Resume + Batch Monitor
4. Derived Variables + หลาย Filter
5. Result file + เขียนกลับต้นทางพร้อม Backup
6. ปรับความเข้ากันได้ของ Excel/CSV และทำ Regression test เต็มระบบ
