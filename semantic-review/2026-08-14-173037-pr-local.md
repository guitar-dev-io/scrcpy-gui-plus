# Asynchronous auto-scroll capture with adaptive stitching

This change adds per-device asynchronous auto screen capture with pause, resume, stop, cancel, stability sampling, overlap alignment, fixed-band removal, bounded stitching, and typed Tauri events. Frames come from the existing bounded ADB PNG provider, while gestures prefer an already-connected scrcpy control socket and fall back to argv-based ADB input only when no usable embedded session exists. UIAutomator contributes an optional scrollable-region hint, and the exporter reuses the existing filename and atomic-write helpers without introducing another video decoder or scrcpy server. Four correctness gaps remain around terminal command arbitration, shutdown registration, memory enforcement, and use of detected region geometry.

**Watch for:** **confirmed** stop/cancel can be accepted after the final export check yet lose to COMPLETED; **confirmed** shutdown can miss a job registering behind its registry sweep; **confirmed** `maxMemoryMb` does not bound all simultaneously retained buffers; **confirmed** detected/manual regions do not steer the swipe and can be missed entirely.

**Verdict**: NEEDS_CHANGES

## High-level view

The capture task samples ADB screenshots until two stable comparisons, aligns each settled frame against the previous viewport, and appends only new rows. It reuses the existing scrcpy control socket, and a control write failure does not retry through ADB because the first gesture may have been partially delivered.

Region discovery affects cropping, stability, overlap, and sticky-band removal, but not gesture placement. **Confirmed:** AUTO still swipes at full-screen x=50%, y=78% to 28%, so a selected side pane or bounded manual region can receive no touch and be reported as complete after two unchanged attempts.

The registry uses per-device active entries and generation-safe removal, but terminal lifecycle decisions are not serialized. **Confirmed:** stop/cancel can race the final result commit, and the one-time shutdown sweep can complete before an in-flight registration inserts its job.

The segment builder checks stored RGBA rows plus its future final canvas, while the controller separately checks stored rows plus optional PNG frames. **Confirmed:** those checks omit one another and the live full-frame/cropped buffers, so actual peak memory can exceed `maxMemoryMb` even when every check passes.

<summary>Issues (4)</summary>

1. **Terminal command lost after export (confirmed)** — Stop or cancel can be accepted after the last signal check but before result publication, allowing COMPLETED output or an orphaned file. Atomically seal terminal publication and retain cleanup ownership until metadata commits.
2. **Registration after shutdown sweep (confirmed)** — A start that read `shutting_down=false` can insert after shutdown has permanently finished clearing the registry. Recheck shutdown state under the registry lock or synchronize both operations as one transition.
3. **Incomplete `maxMemoryMb` accounting (confirmed)** — Separate builder and PNG checks omit each other and several live RGBA buffers, and PNG clones are checked only after allocation. Use shared pre-allocation reservations for the entire job and release obsolete buffers before final encoding.
4. **Region-independent swipe coordinates (confirmed)** — Detected/manual regions affect analysis but AUTO gestures remain viewport-relative, so off-center regions can be untouched and falsely terminate as CONTENT_END. Derive AUTO coordinates inside the effective region and test bounded side panes.

## Stop and cancel are not sealed before result publication

**Confidence: confirmed.** `finalize_capture` checks the atomic control signal after `spawn_blocking` returns, then calls `finish_with_output` without atomically sealing the job against later commands (`src-tauri/src/auto_capture/controller.rs:1220-1228`). A stop or cancel accepted in that interval updates `JobControl`, but `finish_with_output` never reads it; it writes the result and transitions from STITCHING to the previously selected terminal status (`controller.rs:1231-1254`). A cancel can therefore return successfully while the job publishes COMPLETED and leaves the PNG in place, and a stop can publish COMPLETED rather than STOPPED.

```text
export file -> check RUNNING -> [cancel/stop accepted here] -> publish COMPLETED
```

Shutdown makes the same gap capable of orphaning output. `shutdown` marks session metadata CANCELLED immediately. If that happens after the post-export signal check, `finish_with_output` assigns `session.result` before its transition; the transition from CANCELLED fails, later cancellation cleanup clears the metadata, but `SavedCapture` has no drop cleanup and the exported file remains on disk. Terminal publication needs one arbitration operation that either consumes a pending stop/cancel or seals the job so later commands are not reported as accepted, and the saved output should remain guarded until the terminal metadata commit succeeds. The existing control test exercises sequential atomic operations only; add a barrier-controlled test at the post-export/pre-commit boundary, including shutdown and output cleanup.

## Shutdown can sweep before registration inserts the job

**Confidence: confirmed.** `register` reads `shutting_down` before acquiring `registry`, whereas `shutdown` flips the flag, acquires that mutex, cancels the current entries, clears the active map, and becomes permanently idempotent (`src-tauri/src/auto_capture/controller.rs:171-218`, `289-306`). This interleaving is allowed:

```text
start:    read shutting_down=false -------- wait for registry lock ---- insert job
shutdown:                set true -> lock -> clear active jobs -> unlock
```

The newly inserted task is absent from the only shutdown sweep, and subsequent `shutdown` calls return early because the flag is already true. It can continue capturing or exporting while the application is closing. Recheck `shutting_down` while holding the registry lock used for insertion, or make registration and the shutdown sweep one synchronized state transition. The current shutdown test registers first and then shuts down, so it cannot expose this ordering.

## `maxMemoryMb` is not a whole-job memory ceiling

**Confidence: confirmed.** `LongScreenshotBuilder::ensure_totals` admits a segment when `stored RGBA + final canvas <= limit` (`src-tauri/src/auto_capture/stitcher.rs:138-158`). `ensure_raw_frame_budget` independently admits saved PNGs when `stored RGBA + PNG bytes <= limit` (`src-tauri/src/auto_capture/controller.rs:1525-1539`). If stored segments, the future canvas, and retained PNGs are each 45% of the configured limit, both checks pass while those three allocations alone total 135%.

The normal path also retains `builder.segments`, a full `previous` screenshot, `last_cropped`, and stability's full `latest` and `next` screenshots at the same time. Final stitching allocates the canvas while controller resources and optional individual PNGs remain owned, and the non-stitch path clones `last_cropped` during PNG encoding. The individual-frame path also clones and pushes each PNG before calling `ensure_raw_frame_budget`, so rejection happens after the extra allocation. Replace the split checks with shared reservation accounting, release obsolete full frames before final allocation, and test peak accounting through the controller rather than only the isolated builder.

## Scrollable bounds do not affect gesture coordinates

**Confidence: confirmed.** UIAutomator/manual bounds flow into `resources.region` for cropping, stability, overlap, and fixed-band handling, but `perform_scroll` receives only the full screenshot width and height (`src-tauri/src/auto_capture/controller.rs:623-652`, `1001-1020`). It converts configured ratios directly against the viewport. For example, a valid right-pane region `[700, 100][1080, 2200]` on a 1080-wide display is cropped and analyzed, while AUTO sends the touch at x=540 outside that node.

```text
UIAutomator/manual region -> crop + compare + stitch
full screenshot dimensions -> fixed ratio coordinates -> scrcpy control / ADB input
```

After the wrong target stays unchanged, stability succeeds and the identical-frame path contributes two end confirmations, producing a successful single-viewport CONTENT_END result rather than identifying that the selected scrollable region was never moved. Derive AUTO coordinates inside the effective region, define whether CUSTOM remains viewport-relative, and cover off-center and vertically bounded regions.
