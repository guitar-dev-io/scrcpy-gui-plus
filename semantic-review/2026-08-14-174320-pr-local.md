# Region-aware Auto Capture with sealed output publication

This follow-up retains the MVP architecture: ADB PNG acquisition, UIAutomator hints, existing scrcpy control gestures, stability sampling, overlap stitching, and atomic PNG export. It seals the prior export race, synchronizes registration with shutdown, reserves whole-job image memory, and scales every gesture preset inside the effective capture region. Stop arbitration remains incomplete when a worker failure wins concurrently, and public commands discard the terminal seal's rejection result. Bounded regions also use a full-viewport movement threshold, allowing valid short scrolls to be mistaken for content end.

**Watch for:** **confirmed** an accepted stop can become FAILED and lose aligned frames when capture/processing fails concurrently; **confirmed** stop/cancel/pause/resume can return a successful stale snapshot after `CONTROL_FINISHED` rejects the command; **confirmed** a SHORT swipe in a small detected/manual region can add real rows yet count as `NoNewContent` because the threshold uses full-screen height.

**Verdict**: NEEDS_CHANGES

## High-level view

The job remains one asynchronous task per device. It captures through the existing bounded ADB PNG service, prefers an existing scrcpy control socket, and uses argv-based ADB input only when no usable embedded session exists; partial scrcpy writes are not retried through ADB.

Final output publication now has one atomic winner, and shutdown cannot admit a job behind its registry sweep. **Confirmed:** failure finalization gives only cancel priority, so a stop accepted while capture or processing returns an error becomes FAILED after the accumulated builder is dropped.

The revised reservations include retained segments/frame PNGs, stability probes, overlap crops, thumbnails, prospective segments, and final encoding; obsolete source frames are dropped before canvas allocation. This closes the prior split-accounting gap.

Detected/manual bounds now drive AUTO, fixed, and CUSTOM gestures. **Confirmed:** continuation still requires two percent of full screenshot height rather than effective-region height, so valid movement in a short pane can produce two false end confirmations.

`cargo test auto_capture --lib` passes all 24 targeted tests, and `cargo fmt -- --check` plus `cargo check` are clean. **Confirmed, not tested:** public command behavior across seal/commit, stop-versus-failure arbitration with retained frames, and bounded-region continuation thresholds.

## Stop arbitration does not survive a concurrent worker failure

**Confidence: confirmed.** After one frame is accepted, stop can set `CONTROL_STOP` while the next capture, decode, overlap, or memory check is in flight. An operation error returns `RunAbort::Failure` without another signal checkpoint (`src-tauri/src/auto_capture/controller.rs:1036-1077`), then `run_capture_loop` unwinds and drops `CaptureResources` before `finish_failed` runs (`controller.rs:565-567`).

`finish_failed` seals the control word but handles only `FlowSignal::Cancel`; `FlowSignal::Stop` falls through to FAILED with no result (`controller.rs:1445-1469`). The same accepted stop therefore produces a partial STOPPED PNG when capture succeeds but FAILED with no PNG when capture reports an error.

```text
frame 1 retained -> capture frame 2 in flight -> stop accepted
                                        \-> capture error -> resources dropped -> FAILED
```

Arbitrate the error while the builder remains owned: finalize STOPPED when stop won and a usable frame exists; otherwise seal failure before rejecting a later stop. Add a barrier test that releases an in-flight operation with an error after stop is accepted.

## Public commands ignore rejection by the terminal seal

**Confidence: confirmed.** `pause_auto_capture`, `resume_auto_capture`, `stop_auto_capture`, and `cancel_auto_capture` discard the boolean returned by `JobControl` and unconditionally return a snapshot (`src-tauri/src/auto_capture/controller.rs:481-516`). After finalization sets `CONTROL_FINISHED`, the mutations are rejected internally (`controller.rs:98-155`), but a command that acquired the active handle before sealing can still return `Ok(STITCHING)` before `finish_with_output` commits COMPLETED.

The export is protected, but the API reports success for a command that had no effect. Propagate a typed outcome or synchronize terminal metadata with sealing so rejection returns the committed terminal state. The seal test covers only the atomic primitive, not a command across the seal/commit boundary (`controller.rs:1805-1821`).

## Full-screen movement threshold misclassifies bounded panes

**Confidence: confirmed.** Coordinates are region-relative, but continuation requires `overlap.new_content_rows >= (dimensions.1 * 2 / 100).max(8)`, using full screenshot height (`src-tauri/src/auto_capture/controller.rs:863-878`). On a 2400-pixel display this requires 48 rows. A 200-pixel pane in SHORT mode moves about 36 rows because the preset spans 18 percent of the effective region (`src-tauri/src/auto_capture/model.rs:447-455`); even an exact overlap is recorded as `NoNewContent`, and two attempts terminate as CONTENT_END with content remaining.

Use effective-region height for the relative floor and test a vertically bounded pane through overlap and end detection. The current region test checks gesture endpoints only.
