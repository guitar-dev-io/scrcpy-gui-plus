# Region-aware Auto Capture with race-safe terminal control

This follow-up retains bounded ADB PNG capture, existing scrcpy control gestures, UIAutomator hints, adaptive stability sampling, and atomic PNG export. It closes the prior stop-versus-failure race, terminal command publication race, and bounded-pane end-threshold gap. Shutdown registration and whole-job memory accounting also remain sealed from the first review. One defect remains: upper-screen regions are passed to a matcher anchored at 25% of the full viewport, so valid scrolling can fail alignment without examining the pane.

**Watch for:** **confirmed** UIAutomator/manual regions ending above the viewport’s 25% anchor plus 64 rows always return no overlap and typically fail with `IMAGE_PROCESSING_FAILED`; make overlap search coordinates relative to the effective region and cover an upper-screen pane.

**Verdict**: NEEDS_CHANGES

## High-level view

The task captures through the existing bounded ADB provider, waits for two stable comparisons, and stores only newly exposed rows. Gestures stay inside the effective region, prefer an established scrcpy control socket, and use argv-based ADB input only when no usable embedded session exists.

The previous lifecycle findings are addressed: retained frames survive stop-versus-failure arbitration, terminal sealing and metadata publication share the session lock, and registration rechecks shutdown under the registry lock. Reservations now cover retained and transient image buffers through final encoding.

Gesture coordinates and end thresholds are region-relative, but overlap alignment still uses the legacy matcher’s full-viewport vertical anchor. **Confirmed:** on a 2400-row screenshot, region `[0,100][1080,500]` starts matching at row 600 and immediately returns no overlap because the region ends before row 664.

The transport change stays within validated ADB argv and an existing local scrcpy control socket; it adds no listener, shell interpolation, credential flow, video decoder, or second scrcpy server. Partial control writes are not retried through ADB, avoiding duplicate gestures.

All 27 targeted tests and 181 non-ignored library tests pass; the hardware smoke test remains ignored. `cargo fmt -- --check`, `cargo check`, and `git diff --check` are clean. **Confirmed, not tested:** overlap in a bounded pane whose bottom lies above the full screenshot’s 25% matcher anchor.

## Upper-screen scroll regions never reach overlap scoring

**Confidence: confirmed.** `OverlapDetector` passes the effective region’s absolute `top` and `bottom` to `find_vertical_overlap` (`src-tauri/src/auto_capture/algorithms.rs:158`). The helper sets `match_top` to `max(region.top, full_frame_height * 25%)` and returns `None` when `region.bottom <= match_top + 64` (`src-tauri/src/screenshot.rs:414-417`). A 400-row pane from row 100 through 500 on a 2400-row frame therefore exits before comparing a pixel.

```text
2400-row screenshot
0 -------- pane top 100
|          scrollable content
500 ------ pane bottom
600 ------ full-viewport 25% anchor
664 ------ minimum matcher bottom
```

No region-relative continuation threshold is reached because no `OverlapResult::Match` exists. After a real scroll, the controller receives `OverlapKind::None` and, unless the changed pane satisfies the nearly-stable fallback, fails with `IMAGE_PROCESSING_FAILED` (`src-tauri/src/auto_capture/controller.rs:909-927`). Both UIAutomator and manual regions are affected.

Crop the Y range before invoking the legacy matcher and map the overlap back to screenshot coordinates, or derive matcher anchors and ambiguity distances from `bottom - top`. The current bounded-region test uses rows 1000-1200 on a 2400-row frame, safely below the 600-row anchor; add a pane above that anchor.
